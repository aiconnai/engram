# Migrating cache-clear consumers to Engram 0.24.0

Status: migration instructions for the prepared core 0.24.0 candidate and SDKs 0.7.0.
Publication is pending. The change landed in [PR #247](https://github.com/aiconnai/engram/pull/247).

## Affected callers

The JSON payload returned by `memory_cache_clear` is now identical for global,
explicit-workspace and principal-bound calls. Callers that inspect the old
workspace-specific keys must update their parsers and snapshots before upgrading.
This changes the successful tool payload inside the existing MCP response envelope.

| Successful call | Before #247 | Prepared 0.24.0 |
|---|---|---|
| Global `memory_cache_clear` | `{"success": true, "entries_cleared": N}` | Same shape |
| Workspace-scoped or principal-bound `memory_cache_clear` | `{"cleared": true, "scope": "workspace", "workspace": "alpha"}` | `{"success": true, "entries_cleared": N}` |

`N` is the number of entries evicted. Zero is a successful no-op, so check `success`
rather than the truthiness of `entries_cleared`. The response no longer echoes the
workspace; retain it from the request or authenticated context if the UI needs it.

`search_cache_clear` keeps its existing `{cleared, scope[, workspace]}` response.
Do not change a shared parser for both tool names without dispatching by tool name.
Authorization failures still use the structured error payload; they must not be
interpreted as successful clears or retried with broader permissions.

## Updating applications

1. Find direct MCP calls and wrappers that read `cleared`, `scope` or `workspace` from
   `memory_cache_clear`. Python `client.cache_clear(workspace="alpha")` and TypeScript
   `client.cacheClear({workspace: "alpha"})` forward this tool's successful payload.
2. Read `success === true` and an integer `entries_cleared >= 0` on the new server.
   Update fixtures for explicit workspaces, principal-bound calls and an empty cache.
3. If supporting old and new servers during rollout, accept the old `cleared === true`
   response only for the legacy `memory_cache_clear` success case. Treat the old count
   as unknown, not zero. Check tool errors before either success format; reject unknown
   payloads. Remove the legacy branch when the supported server range allows it.
4. Keep workspace authorization enabled. Never drop `workspace` from a request to work
   around a denial. The server also closes cross-workspace batch writes in this release.

The SDKs default search `limit` to 20 instead of 10. Applications requiring the prior
page size should pass `limit=10` (Python) or `limit: 10` (TypeScript) explicitly and
verify pagination using `offset`.

## Consumer notice draft

> Engram core 0.24.0 and SDKs 0.7.0 are being prepared. Before upgrading, update any
> parser for workspace-scoped `memory_cache_clear`: the success payload changes from
> `{cleared, scope, workspace}` to `{success, entries_cleared}`, matching global clears.
> An empty cache returns `success: true` and `entries_cleared: 0`. `search_cache_clear`
> retains its current payload. SDK search defaults increase from 10 to 20; pass an
> explicit limit if your application needs the former page size. Test the parser and
> pagination changes in staging. Release availability will be announced after approval.

This is a draft for the release owner to send through the established consumer
channels. No message has been sent as part of this preparation.

For the separate Rust/build change removing Turso/libSQL, see the
[Turso sunset guide](turso-sunset.md).
