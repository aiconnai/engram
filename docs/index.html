ii anatomy of memory

Workspaces. Sessions. Entities. Drawers.

A structured cognitive architecture built in Rust. Broad workspaces partition projects; sessions record time-based context; entity graphs link concepts; verbatim drawers preserve immutable decisions.

W — WORKSPACE

The Workspaces

projects · environments · teams

Strict cryptographic isolation per project. Distinct databases or segregated schemas prevent context contamination between repos.

S — SESSION

The Sessions

days · transcripts · threads

Chronological units of time. Auto-indexed chat transcripts and scratchpads that decay dynamically unless promoted to permanent memory.

E — ENTITY GRAPH

The Entities

concepts · systems · identities

Bidirectional relationships linking facts. Canonical identity resolution unifies aliases (e.g. AuthService $\to$ auth-api).

D — DRAWER

The Drawers

verbatim · decisions · immutable

The exact chunk of verbatim content. Full fidelity with timestamp, salience score, provenance, and contradiction guardrails.

iv mechanics

Four Pillars. No Cloud. No Keys.

Engineered from scratch in Rust for uncompromising privacy, performance, and determinism.

— 01

Local-First

SQLite with Write-Ahead Logging on disk. Nothing is uploaded. Zero telemetry. Your memories live under a single directory on your machine.

default path · ~/.local/share/engram/memories.db
— 02

Zero API Keys

3-way search (BM25 FTS5 + local MiniLM ONNX vectors + fuzzy distance) runs 100% on CPU. No OpenAI key or cloud embedding endpoint required.

cloud keys required · none
— 03

Background Hooks

Ingestion and indexing happen silently via lifecycle hooks on session end or compaction. Agents query durable context without rebuilding history.

hook budget · <50 ms
— 04

Temporal Graph

Entity relations with valid-from and valid-to timestamps. Detects contradictions when requirements change and guides automated resolution.

conflict engine · temporal resolution

Developer SDKs & Configuration

Integrate in Minutes

Use Engram from Rust, Python, TypeScript, CLI, or configure as an MCP server for your favorite agent.

// Cargo.toml: engram-core = "0.24.0"
use engram_core::{EngramEngine, MemoryBuilder, SearchQuery};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let engine = EngramEngine::open_local("~/.local/share/engram/memories.db")?;

    // Create a permanent memory
    let memory_id = engine.store_memory(
        MemoryBuilder::new("PostgreSQL connection pool sized to 25 connections")
            .workspace("backend")
            .memory_type("decision")
            .salience_boost(0.95)
            .build()?
    ).await?;

    // 3-way hybrid search (BM25 + Vectors + Fuzzy)
    let results = engine.search(SearchQuery::new("postgres conn pool").workspace("backend")).await?;
    for hit in results {
        println!("Found [score {:.2}]: {}", hit.score, hit.content);
    }
    Ok(())
}
