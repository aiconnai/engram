# SDK 0.7.0 — release notes draft

Packages: Python `engram-client==0.7.0` and npm `engram-client@0.7.0`.
Both versions are prepared locally; neither package is published by this document.
They version independently from core. The declared core range remains 0.20.0–0.24.x
in [channel-matrix.toml](channel-matrix.toml); the candidate tests use core 0.24.0.
That declaration is not fresh test evidence for every historical core release.

- Public resource methods align with the server tool registry; resource requests use
  JSON-RPC `resources/*`. The contract drift baseline contains no accepted drift entries.
- TypeScript normalizes MCP `isError: true` failures into `EngramError` with message,
  code and details, including timeout/connection error handling.
- Search defaults to 20 results and accepts `offset`; Python also exposes
  `include_archived`. Pass an explicit limit to retain 10-result pages.
- Cache-clear wrappers forward the server's payload. Core 0.24.0 standardizes
  `memory_cache_clear` to `{success, entries_cleared}`; migrate callers that consume
  the old scoped payload using the [migration guide](../migrations/v0.24.0-cache-clear.md).
- Markdown vault import (`vault_import` in Python, `vaultImport` / `vault.import` in
  TypeScript, `ImportOptions::default()` in Rust, and `engram-cli import markdown`)
  now defaults to RFC 0004 review/dry-run mode (`confirm=False` / `confirm: false`),
  matching the `memory_import_markdown` MCP tool schema and returning `dry_run` in the
  import report. Pass `confirm=True` / `confirm: true` (or `--confirm` on the CLI) to
  apply writes.
- TypeScript `engram-client@0.7.0` requires **Node.js >= 22.12** (`engines.node: ">=22.12.0"`),
  matching its `vitest` 5 / `@types/node` 22 verification toolchain.
- Both Python `embedding_migrate(dry_run=True, target_model=...)` and TypeScript
  `admin.embeddingMigrate({ dryRun: true, targetModel })` expose read-only migration counts
  and raise/throw `EngramError` when `dry_run` is omitted or `false` (use
  `memory_rebuild_embeddings` for active-model re-embedding).
- Markdown import/export additionally enforces filesystem roots, permission modes,
  stored-workspace authorization and explicit error outcomes. Review the
  [import](../migrations/v0.24.0-markdown-import-security.md) and
  [export](../migrations/v0.24.0-markdown-export-security.md) migration notes before automation.

The [consumer notice draft](v0.24.0-consumer-notice.md) packages these changes for owner-approved delivery.

Before publication, approve the exact core tag/SHA, verify installable artifacts and
run the installed-package live contracts. Publish each SDK channel separately through
the protected environments described in [SDK_PUBLISHING.md](SDK_PUBLISHING.md).
