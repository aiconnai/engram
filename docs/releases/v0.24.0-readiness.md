## Local packaging

Packaging `engram-core` alone cannot resolve the unpublished `engram-types` from crates.io.
Prepare both interdependent crates together, with no registry upload:

```bash
cargo package -p engram-types -p engram-core --registry crates-io --offline --target-dir /tmp/engram-pkg-verify
```

Repeat from the clean, reviewed release SHA before publication. Root-cause diagnosis (`R4`)
confirmed that Cargo 1.96.0 succeeds with full archive verification (`exit 0`) when the
staging `target-dir` has not been poisoned by an earlier `cargo package --no-verify` run
(which writes unpackaged index entries into `target/package/tmp-registry` without checksum
hashes, triggering `no hash listed` on subsequent verified runs). Always use a clean
`--target-dir` (or omit `--no-verify` from the start); real publication still requires
`engram-types` to become available on crates.io before publishing `engram-core`. See [Cargo package documentation](https://doc.rust-lang.org/cargo/commands/cargo-package.html)
for interdependent package selection and registry assumptions.
